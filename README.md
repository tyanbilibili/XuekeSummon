# 《学科召唤》 Online

参考《原神·七圣召唤》桌游化设计的学科卡牌对战游戏，已实现为一个可通过**局域网联机**的网页版。

这是七圣召唤刚推出的那个版本的时候，本人试图将其桌游化而作出的一些尝试。而现在借助AI，0代码基础的本人也是终于将它端出来了。

- **注意**：该项目目前处于超级早期的版本，可能会有一堆程序问题。有问题务必反馈，等我和AI扯皮。

## 功能

- **人机对战（PvE）**：与内置 AI 对战。
- **局域网联机（PvP）**：一台机器作主机（`localhost`），另一台设备用局域网 IP 进入同一房间号。
- **自选队伍**：开局前必须从 9 位角色中自选 3 位并确定站位顺序（点击顺序 = 站位，槽位可左右调整）。
- **卡组装配**：首页「卡组装配」可自由搭配手牌（每张最多 2 张、整组最多 30 张），支持分类筛选、一键填充与本地保存。
- **学科图鉴**：首页「图鉴」可查阅全部 9 位角色技能与 58 张手牌效果。
- **二级确认操作**：点击手牌在右侧查看效果并选择「打出 / 调和」；点击角色卡在左侧查看状态与技能，并选择「切换 / 普通攻击 / 元素战技 / 元素爆发」，避免误操作。
- **全行动特效**：出牌、技能施放、伤害、掷骰均有独立动画（卡牌放大散粒、技能名展示、光球飞向目标并弹出伤害数字、骰子结果弹窗），人机 AI 会随机思考 1.5~4.5 秒。
- **召唤物/场景专区**：双方角色区下方设独立区域展示召唤物、场景牌、支援牌，点击可查看名称、效果与剩余回合/次数。
- **手牌快速行动**：除“首次装备”为快速行动、“更换装备”额外 +2 行动点且视为作战行动外，其余手牌默认均为快速行动。
- **出招前伤害预览**：角色普攻/战技/爆发按钮与部分会造成伤害的卡牌会显示“预计伤害”。
- **图鉴扩展**：新增「元素反应」「召唤物」两个图鉴条目，便于查阅反应与召唤物说明。
- 完整实现 9 位学科角色（语文/数学/英语/物理/化学/生物/政治/历史/地理）、文/理元素、大/小体型特性。
- 三种元素反应：中和（文+理）、应激（理+理）、失忆（文+文）。
- 行动点 / 骰子 / 先手机制，一回合内“你一下、我一下”多次交替行动，提前结束可获下回合先手。
- 召唤物、护盾、易伤、迷彩、眩晕、流血等 buff/debuff、回合结束判定顺序（食物 > 召唤物 > 回血 > 清除 > 抽牌）。
- 全部 **58 种手牌**（武器 / 饰品 / 天赋 / 共鸣 / 场景 / 支援 / 料理）均已实现主要效果。
- 第 10 回合触发「疲劳」（一切消耗+1），第 15 回合未分胜负判平局。
- 所有素材来自工作区 `远古想法、素材库/`（角色卡、手牌、元素图标、召唤物图标、buff 图标），已转为网页用图。

## 如何运行

前置：Node.js（已用 v24 开发）。仅需 `ws` 一个依赖。

### 方式一：双击即玩（人机对战，无需服务器）
直接双击打开 `web/index.html`（或把它复制到任意文件夹双击）。
页面会使用内置的离线引擎与 AI，**人机对战**完全不需要 `localhost` 服务器。

> 只有选择「局域网联机（PvP）」时才需要启动服务器。

```powershell
# 1) 安装依赖
npm install

# 2) 启动服务器（默认端口 8080）
npm start
# 或
node server.js
```

> 如果修改了 `data/` 或 `game/` 中的规则代码，请重新生成离线包：
> `npm run build:offline`

启动后终端会打印本机与局域网地址，例如：

```
本机访问:   http://localhost:8080
局域网访问: http://192.168.2.53:8080
```

### 人机对战
在本机打开 `http://localhost:8080`：

1. 选择「人机对战」。
2. 在“出征队伍”中点击角色，按顺序凑满 3 位；可用槽位上的 ◀ ▶ 调整站位。
3. 点「前往装配」配置卡组（也可直接开战，未配置会自动生成默认卡组）。
4. 输入名字，点「开 始 对 战」。

对局中：

- 点击手牌 → 右侧信息面板 → 「打出」或「调和」。
- 点击角色卡 → 左侧信息面板 → 查看状态/技能，并在「行动」区点击招式；出战角色的普攻/战技/爆发按钮只在轮到你的行动轮出现。
- 出招后行动权交回对方，回来后可再次出招（只要行动点足够）。
- 点击角色区下方的召唤物/场景/支援图标可查看说明；战斗日志会同步记录。

> 请务必通过 `http://localhost:8080` 打开页面，不要直接双击 `index.html`（联机与数据接口需要服务器）。若服务器后启动，页面会自动重试连接。

### 局域网联机
两队各在一台设备（须连同一局域网）打开页面：

- **主机**：选择「局域网联机」，填一个房间号（如 `r1`），点开始 → 等待对手。
- **访客**：选择「局域网联机」，填**相同房间号**，点开始即可加入。
- 你也可以直接把终端打印出的 `http://<主机IP>:8080` 发给对方，对方用该地址打开页面即可。

> 说明：默认 2 人对战。联机时请确保防火墙放行 8080 端口。

## 玩法摘要

- 双方各选 3 名角色并决定出战位，抽 5 张初始牌（可换一次）。
- 开局掷骰决定先手；每回合前双方各掷 2 骰，行动点 = ⌊10 − 骰差/2⌋（向下取整；例如掷出 1、4 → 8），并有小体型、场景、支援等加成。
- 每回合内双方交替行动：可用行动点进行普攻、战技、爆发、切人、打手牌、调和（弃牌换行动点）等；普攻/切人/大部分手牌会结束你的**行动轮**（把行动权交给对方），但之后你可再次行动；选择「提前结束」则获得下回合先手。
- 回合结束后按「食物 > 召唤物 > 回血 buff > 到期 buff/debuff > 抽 2 张牌」结算。
- 角色全部阵亡即败；第 10 回合起所有消耗 +1；第 15 回合未分胜负则平局。

## Codex对规则中模糊处的处理（可自行调整）

数字版中一些「实体桌游」的交互做了合理简化，可在 `game/` 下修改：

- **行动点公式**：按 `⌊10 − 两骰差/2⌋` 实现（取整向下），已修正为规则文档写法。
- **小体型**：行动点加成 = `min(队伍中小体型角色数, 2)`。
- **大体型**：每次回合末自动 +4 血（整局最多 3 次，仅在未满血时触发）。
- **语文天赋 / 数字奥法之卷**的「知识提问」：数字版以问答弹窗形式呈现，是否答对暂不影响接下来的数值/先手（避免打断回合流程），后续可接入。
- 个别卡牌交互（如「食堂」「精准打击」等）采用简化处理，核心数值与效果已按文档实现。

## 演示模式

在地址后加 `?demo=1` 会自动开始一局人机并对局并自动行动，便于演示/截图：
`http://localhost:8080/?demo=1`
加 `&pause=1` 则只在开局后停下，便于查看界面。

## 把“联机版”分享给朋友（GitHub 仓库 / Release）

联机模式需要 Node 服务器，**不能**通过 GitHub Pages 直接联机。推荐两种方式：

### GitHub Release 压缩包
项目内置打包脚本，一条命令生成可直接分发的 zip（约 18MB，已含全部网页素材、规则、AI，
已排除 `node_modules`、原始大素材与临时文件）：

```powershell
npm run build:release
# 产物：dist/xueke-summon-1.0.0.zip
```

然后在 GitHub 仓库页面：`Releases → Create a new release`，把这个 zip 作为附件上传即可。
朋友下载后：解压 → 双击 `start.bat`（Windows）或运行 `bash start.sh`（macOS/Linux）→ 自动装依赖并启动。

### 朋友如何联机
1. 一个人运行 `start.bat`（或 `npm start`），记下终端打印的 `http://<主机IP>:8080`（如 `http://192.168.2.53:8080`）。
2. 双方打开该地址，选择「局域网联机」，填**相同房间号**（如 `r1`）→ 开始。
3. 注意：Windows 防火墙需放行 8080 端口；两台设备在同一局域网（同一 Wi-Fi/路由器）。

> GitHub Pages 版本仍可单机/人机对战（内置引擎），但**联机请用上面的本地启动方式**。
